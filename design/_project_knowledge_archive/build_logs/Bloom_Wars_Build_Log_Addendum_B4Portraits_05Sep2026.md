# Build Log Addendum — B4: Portrait Wiring, 5 September 2026

Closes the "portraits wiring" line that's sat on the feature-gap report and the Now & Next "Table-stakes polish still unbuilt" list since 1 September. Handoff doc: `Bloom_Wars_Sitrep_Handoff_B4_Portraits_05Sep2026.md`, which scoped the pass into four jobs — asset prep, making the assets reachable by the build tool, a real image-loading pipeline, and swapping the placeholder colored-circle-plus-initials for real portraits everywhere a pilot's face shows up. All four are done and verified; **nothing here has been watched on Maxime's own machine yet** — see the open item at the end.

## The pipeline

The game had never loaded an image asset before this pass — every existing visual is drawn shapes (circles, rectangles, text). `src/scenes/Preloader.ts` is new: a real Phaser preload scene that loads every portrait and splash file before Boot hands off to the title flow, so a mission load or a Hub open never blocks on a network fetch mid-scene. `src/engine/portraits.ts` is the cache-key convention every scene now shares — one function resolving a `pilotId` to a texture key (`portrait_<id>` for the 20-ish named cast, a deterministic `(n-1) % 12` mapping for the numbered `pilot_recruit_N` pool onto a fixed 12-portrait generic set, so a recruit always shows the same face across a save rather than a random one each load).

`drawPilotAvatar()` (in `TransporterPad.ts`, exported, now the one function every portrait-bearing scene calls) is the fallback contract: if the resolved texture exists in cache, draw a real square portrait `Image`; if it doesn't (a pilot id with no art, or something Preloader missed), draw the original filled-circle-plus-initials placeholder exactly as before. It always hands back a live interactive hit-circle too, invisible under a real portrait, so every existing `.setInteractive()`/`.disableInteractive()` call site across the codebase needed zero changes.

## Asset decisions

Portraits are square, not circle-masked — a deliberate call, not an oversight; circle-cropping in code was tried and looked worse than a clean square with the UI's existing circle chrome around it. Splash art (used in a couple of higher-resolution contexts) is separate from the portrait set and downscaled/recompressed to keep the pass's total asset footprint small. **The original 1024px portrait masters are staying in git history for this pass** — not extracted to a separate LFS-style store or discarded — a size/complexity tradeoff call made to ship this pass rather than build asset-pipeline infrastructure the project doesn't have yet. Worth revisiting if the repo's size becomes a real problem later, but not now.

## The five scenes

`TransporterPad.ts` and `Hub.ts` got the straightforward swap — both already had a placeholder circle to replace, so this was a drop-in call to `drawPilotAvatar()` at each existing draw site (5 squad-row portraits on the Transporter Pad, the Hub's roaming NPCs plus the player's own avatar).

`RosterPanel.ts` and `MemorialPanel.ts` had no placeholder to swap — both were pure text lists — so this pass added a real left-gutter portrait column to each from scratch.

`Debrief.ts`'s earnings panel was the real rework, and it's the reason this pass took a decision rather than just being a mechanical swap: the panel's per-pilot rows were drawn at a flat 15px line height, dense enough for text but not enough to fit a face next to it. Maxime's call, asked directly rather than assumed: **"Do all 5 now, including the Debrief rework."** The panel's row height for pilot rows went from 15px to 28px (non-pilot summary/company lines stay at the original 15px), with each row's text elements re-centered on the row's new vertical midpoint rather than top-aligned. Everything below the earnings panel in Debrief — the grief callout, the campaign shop, the footer — already computed its own position off the earnings panel's returned height rather than a hardcoded offset, so growing the panel by roughly 65px (5 deployed pilots × 13px) needed no other layout change anywhere downstream. That cascading-layout pattern is worth remembering for the next panel that needs a mid-life resize.

## A real bug this pass found, not one it introduced

Building RosterPanel's new avatar column exposed a genuine pre-existing layout bug: the panel's per-pilot rows are one single multi-line `Text` block (all four lines of a pilot's stat readout joined with `\n` into one `Text` object), but the row's buttons were positioned off a separate hardcoded `ROW_H = 46` constant that was never actually measured against the real rendered text. The true rendered height of a 4-line pilot entry at the panel's font size and line spacing comes out to roughly 63.4px, not 46 — so each successive row's buttons drifted further above their actual text, and by the fifth pilot (Lask, in the seeded test roster) the drift was around 70px: his row's move/trade buttons and his new portrait were floating well above his name. Fixed by measuring the real `Text` object's rendered height after `setText()` and dividing by the roster count, rather than trusting a constant — a fix that's immune to the next font or line-spacing change, not just a patched number. Checked MemorialPanel's own equivalent constant (`ROW_H = 34`) the same way before touching it and left it alone — its real measured drift was about 1px, not a bug worth fixing.

Consistent with the project's own standing lesson (verify a specific claim against the actual current file, don't trust an old comment or an assumed constant) — this is exactly that lesson catching a real bug rather than a hypothetical one.

## Verification

All four passed clean, zero page errors, screenshots confirm correctly-aligned real portraits in every panel.

44 files committed to the real device repo — 7 modified with fresh `expectedMtimeMs` guards re-checked immediately before commit (`main.ts`, `Boot.ts`, `Debrief.ts`, `Hub.ts`, `TransporterPad.ts`, `MemorialPanel.ts`, `RosterPanel.ts`), plus new files needing no guard (`engine/portraits.ts`, `scenes/Preloader.ts`, 27 portrait PNGs, 4 splash JPGs, the 4 new verify scripts).
