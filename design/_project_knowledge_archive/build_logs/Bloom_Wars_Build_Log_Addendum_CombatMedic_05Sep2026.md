# Build Log Addendum — Combat Medic (Munti's 4th and flagship branch), 5 September 2026

Picked via AskUserQuestion after "keep building" — offered against a quick confirmed-shape system and a verify-unwatched-work pass; Maxime picked Combat Medic, the last remaining weapon branch (Suppression Autocannon's own addendum, earlier tonight, had already flagged it as "a different shape of build than everything shipped so far... needs an actual positive heal-tick mechanism, which doesn't exist anywhere in this engine yet").

That framing turned out to be Claude's own assumption, not the design. Put a real design fork to Maxime directly (AskUserQuestion — a new granted heal-over-time ability with its own action-bar button, vs. upgrading Repair itself, vs. something else) rather than guessing, since it was a genuine fork with real engine-scope consequences either way. His answer was simpler than either option on offer: **"triple passive regen. to those within 3 tile of themself."** No new StatusEffect kind, no new ability, no new UI — Combat Medic turned out to be the flagship version of the SAME passive aura Munti already has (`tickMuntiRegen()`, `MUNTI_REGEN_RADIUS`/`MUNTI_REGEN_PER_TURN`, `data/combatTables.ts`), not a new engine capability. Worth recording plainly: the branch-index comment calling this "unbuilt infrastructure" was wrong, and the fix was asking rather than building the more complicated thing it assumed was needed.

## What shipped

Combat Medic (`munti_combat_medic`) — Munti's 4th branch, gated at purchase-order slot 4 (tier A, `WEAPON_BRANCH_COSTS[3]`), same purchase-order-not-branch-identity system every other branch uses. A Munti with this branch equipped projects their passive regen aura at `COMBAT_MEDIC_REGEN_RADIUS` (3 tiles) instead of the plain `MUNTI_REGEN_RADIUS` (2), healing `MUNTI_REGEN_PER_TURN * COMBAT_MEDIC_REGEN_MULTIPLIER` (8 × 3 = 24 HP/turn) instead of the plain 8 — same per-Munti-equipped shape Aegis Ward already established for radius alone, just scaling amount too.

- `data/weaponBranches.ts`: new `WeaponBranchId` `"munti_combat_medic"`; `COMBAT_MEDIC_REGEN_RADIUS = MUNTI_REGEN_RADIUS + 1` (own reasoning below), `COMBAT_MEDIC_REGEN_MULTIPLIER = 3` (Maxime's own literal "triple," kept as a named multiplier rather than a flat HP number); added to `WEAPON_BRANCHES` and `WEAPON_BRANCHES_BY_PATH.munti` (now 4 entries, not 3 — the one path with a real 4th slot, since Rapid Response/Aegis Ward/Field Doctor were all cheap radius/cooldown/range tweaks on the same mechanics and this is the first branch that meaningfully changes the actual healing output).
- `engine/mission.ts`: `tickMuntiRegen()` restructured — it used to be a flat boolean "is any qualifying Munti in range" check, since every Munti healed for the identical `MUNTI_REGEN_PER_TURN` regardless of which one was in range. That no longer holds once Combat Medic heals for a different amount, so the tick now computes, per wounded unit, the **best (highest) applicable amount** across every same-side Munti in range — not a sum, not "whichever was checked first." A squad with both a plain Munti and a Combat Medic Munti in range of the same wounded ally gets Combat Medic's number, once, not both added together. This extends the system's existing "multiple Muntis in range don't stack" rule rather than contradicting it — that rule only ever needed to mean "take the strongest applicable aura" once auras could differ in strength, which they couldn't before tonight.

## One design call, mine, flagged per Foundation's attribution rule

Maxime said "3 tile," and I built `COMBAT_MEDIC_REGEN_RADIUS` as `MUNTI_REGEN_RADIUS + 1` (which equals 3 today) rather than a hardcoded 3. Same reasoning Aegis Ward's own radius constant already uses: if the baseline `MUNTI_REGEN_RADIUS` is ever raised later, this stays meaningfully wider than the base instead of collapsing to equal it. Practical side effect worth naming plainly: Combat Medic's radius is now numerically identical to Aegis Ward's own radius (both derive to base+1) — read that as "Combat Medic = Aegis Ward's reach, plus triple the healing," not a coincidence or a copy-paste. If "3" was meant as a literal, radius-system-independent number, this is a one-line revert (swap the derived constant for a literal `3`).

## Tests

Extended two existing files rather than adding a new one — Combat Medic isn't a new mechanism, it's a parameterization of one `muntiRegen.test.ts` and `campaignEconomy.test.ts` already cover in depth:

- `engine/__tests__/muntiRegen.test.ts` — 5 new tests: heals for triple at the radius edge, does not reach one tile past that radius, caps at maxHp same as the plain aura, heals the Combat Medic Munti itself (not just allies), and — the one genuinely new behavior this branch introduces to the tick function — takes the best applicable amount rather than summing when both a plain Munti and a Combat Medic Munti are in range of the same ally.
- `engine/__tests__/campaignEconomy.test.ts` — 1 new test: gates Munti's 4th branch (Combat Medic) at `WEAPON_BRANCH_TIER_GATE[3]` (A), priced at `WEAPON_BRANCH_COSTS[3]`, mirroring the existing 2nd/3rd-branch cases exactly; also confirms a 5th purchase attempt on an already-4-branch Munti fails cleanly (Munti has no more defined branches to buy).
