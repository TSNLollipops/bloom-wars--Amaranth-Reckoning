## Addendum, 30 Aug 2026: Tier 2 — minigame/verb room gating actually checked the target, not just the player

Consolidated Build Plan (29 Aug 2026), Tier 2. Maxime: "fait tout en batch. 1 a la fois. jusqua ske tu manque de credit" — oui, go, continuing tier by tier after Tier 1's four Hub bugs.

**Root cause, confirmed against the actual code.** Five verbs — the three Rec Room minigames (peg board, poker, fletchers/darts), Share a Drink, and Ask Out — each gate on a specific room at their own call site (`if (this.currentRoomId !== "recroom") ...`, or `"berths"` for Ask Out), correctly, since their furniture (the peg table, the card table, the dart board, the pour, the berths themselves) only physically exists in that one room. But every one of them then picks its actual target via `nearestNpcInRange`, which only ever checked `sameDeck(npc.room, this.currentRoomId)` — same DECK, not same ROOM. `recroom`, `hangarDeck`, and `berths` are three different `RoomId`s that all sit on the same "lower" deck and share one continuous coordinate space with no wall or gap between them at the zone boundary (`ROOM_ZONE_BOUNDS`'s own split) — correct and deliberate for the callers that want that reach (Talk, history/highlights requests, the build-request check: all meant to work across the shared open floor, not one specific room). For the five room-specific verbs, though, this meant the room check only ever verified the PLAYER's own position — never the NPC nearestNpcInRange was about to hand back. Standing in the rec room within `APPROACH_RADIUS` (78px) of the boundary line into hangarDeck or berths is an ordinary distance at a zone seam, not a rare edge case — the bug was reachable in normal play, not just in theory.

**The fix.** `nearestNpcInRange` gained an optional `requireRoom?: RoomId` parameter — when set, candidates are also filtered to `npc.room === requireRoom`, on top of the existing same-deck check. Every caller that doesn't pass it (Talk, history, highlights, build-request) is byte-for-byte unchanged, deck-scoped exactly as before, since that breadth is correct for them and was never the reported problem. The five room-gated verbs now pass their own already-checked room (`"recroom"` for the three minigames and Share a Drink, `"berths"` for Ask Out) — one extra argument at each call site, no new state, no new helper beyond the parameter itself.

**Verification.** `npm run typecheck`, full `npm test` (1139/1139, zero regressions), and the full `npm run lint` (spoiler-lock stage included, skips as expected in this sandbox with `BW_RESERVED_TERM` unset), all clean. Same caveat as every Hub.ts pass this session: this is logic-traced against the actual boundary math (`ROOM_ZONE_BOUNDS`, `APPROACH_RADIUS`), not the live Playwright walkthrough the plan calls for — still outstanding for Tier 1's four fixes and now this one too, see "Still open."
