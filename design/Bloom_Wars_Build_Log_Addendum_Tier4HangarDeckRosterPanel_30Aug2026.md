## Addendum, 30 Aug 2026: Tier 4 — a real roster/gear panel at the Hub's Hangar Deck, reusing the existing shop UI

Consolidated Build Plan (29 Aug 2026), Tier 4 — Hangar Deck roster/stats panel. Maxime: "fait tout en batch. 1 a la fois. jusqua ske tu manque de credit." This one sat on the same fork Tier 3 did — the "Hub Early-Access Readiness Plan" Maxime's parallel session is drafting explicitly flags Workshop/Hangar Deck as "worth a product call on whether [staying thin] is the permanent shape or a placeholder" — so asked directly rather than guessed: build the real thing, reusing the existing shop panel rather than a lighter read-only view.

**What was actually there.** `hangarDeck` has been walkable since the Antfarm Grid shipped (27 Aug) but was purely cosmetic — its own `ROOM_NOTES` entry said so outright ("Roster & deploy management still lives in the Campaign Shop for now"). The real roster/gear/recruit UI already exists, and already scene-agnostic by design: `ShopPanel` (`scenes/shop/ShopPanel.ts`, extracted 25 Aug specifically so `Debrief.ts` and `Hangar.ts` could both drive it against the same live `CampaignState` without two copies drifting apart). It was reachable only by leaving the Hub entirely — back to Mission Select, into the separate `Hangar` scene.

**The fix.** A real interactive point in the Hub's own Hangar Deck room — `HANGAR_SHOP_POINT`, centered in that room's zone, same "walk up, press E" shape as the bay (`BAY_RADIUS`/`isAtBay`) and the doors, with its own dashed marker (`drawHangarShopPoint`, the identical dash-drawing code `drawMusterPoint` already uses) and interact prompt ("E — roster & gear"). Pressing E there opens a real, full `ShopPanel` instance — the same one `Hangar.ts` and `Debrief.ts` use, same live `CampaignState`, same purchases, same recruiting — framed in an overlay card matching this file's own history/highlights overlay convention (title, close button, Esc to dismiss, input fully owned while open).

**The one real gap this needed, closed as a small, additive extension rather than a second implementation.** `ShopPanel`'s two existing callers each dedicate their *entire scene* to it, so neither had ever needed to hide it once built — no `setVisible`/`destroy` existed on the class. Hub.ts needs it as an occasional overlay, on while the player's at the terminal and off otherwise, alongside everything else the scene draws. Added one new public method, `ShopPanel.setVisible(visible)`, toggling its own two (previously fully private) containers — a no-op for `Debrief.ts`/`Hangar.ts` since neither calls it, and everything else about the class (its purchase logic, its layout, its `render()`) is untouched. This is the same "extend the shared thing narrowly" instinct as `pickPointNearDoor` generalizing `pickDoorLanding` earlier this session, applied to a UI component instead of a movement helper.

**Save discipline, a deliberate choice, not an oversight.** `ShopPanel`'s existing callers only ever save when the player explicitly leaves (a footer button) — a purchase made in `Hangar.ts` isn't on disk until then. This Hub already saves immediately after every state-mutating interaction elsewhere in the same file (`persistNpcSocial`'s own header covers why). Matched that stricter, already-established Hub convention instead of importing the more lax one: the panel's `onRender` callback (fired after every purchase, not just the first render — `ShopPanel`'s own header names this) calls `saveCampaignState` directly, so a Hub-side purchase survives a crash or reload the same way everything else the Hub touches already does.

**Verification.** `npm run typecheck`, full `npm test` (1139/1139, zero regressions), and `npm run lint` (spoiler stage included), all clean. Also attempted a full `npm run build` (`tsc && vite build`) for the first time this session, past what any earlier tier checked — caught that this sandbox never had the full scene list staged (Boot/MainMenu/CampaignSetup/etc. — files no earlier tier's work touched or needed), not a defect in this change; `tsc` itself compiled clean before `vite build` hit the missing files. Same caveat as every Hub.ts pass this session: logic- and layout-traced against the real coordinate system (960×640 canvas, `SHOP_CARD_W`=900 fitting inside it, `HANGAR_SHOP_POINT` centered with real clearance in a doorless zone), not click-tested in a live browser.
