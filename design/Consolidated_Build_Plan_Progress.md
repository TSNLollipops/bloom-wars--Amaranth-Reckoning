## Tier 5 — abil_ambush stealth cloak redesign: SHIPPED, verified

Maxime's own spec: "stealth cloak 3 turn, can move whilestealth. can attack while stealth. does 2x dmg after exiting stealth. its to give sweep a pvp use too and make ambush something usefull in game." Ambush was a one-shot reactive trick built on Overwatch's own trigger (concealed + overwatch together, one held shot, gone the instant it fired). Now: activating sets a new `stealthTurnsRemaining` field (3 rounds) alongside `concealed`; the per-round reset loop decrements it instead of blanket-clearing concealment while it's active, so the unit's own later turns are fully normal (move, attack) while hidden. `resolveAttack()` doubles the damage of the specific attack that breaks an active cloak (gated on the new field, not on `concealed` generally, so `abil_screen` is untouched) and tags it "DECLOAK STRIKE" in the log. Separately, `engine/ai.ts`'s `isVisibleTo` had `concealed` checked *before* `revealedUntilTurn` (abil_sensor_sweep's paint) — meaning a swept ambusher stayed invisible regardless — reordered so a sweep now beats concealment the same way it already beat burrow. That reorder is the literal "give sweep a pvp use" half of the request; `abil_sensor_sweep` itself is still player-only (no hostile-side/PvP use exists yet to actually run in), so this is the seam opened, not a finished PvP mode.

Four existing tests that encoded the old reactive-shot behavior were rewritten (they failed exactly as expected the moment the mechanic changed); one new test proves a swept unit is visible through concealment. `npm run sim:batch` run for regression-checking per Tier 0's own precedent — 289/400 (72%), matching baseline, though confirmed the bot's own AI doesn't call `ambush()` at all yet (`playerAi/types.ts`'s own note), so this run confirms non-interference rather than exercising the new mechanic live.
