## Addendum, 30 Aug 2026: Tier 5 — abil_ambush becomes a real 3-turn stealth cloak, and abil_sensor_sweep gets a reason to counter it

Consolidated Build Plan (29 Aug 2026), Tier 5. Maxime: "fait tout en batch. 1 a la fois. jusqua ske tu manque de credit." Unlike Tiers 1-4, this one had no clean match in the plan's own text — three real candidates existed in the code (a stealth-adjacent Meeps posture, a fog-of-war interaction, and Ambush itself), so this was asked directly rather than guessed. Maxime's answer was a full, precise design brief, not just a pick: **"stealth cloak 3 turn, can move whilestealth. can attack while stealth. does 2x dmg after exiting stealth. its to give sweep a pvp use too and make ambush something usefull in game."**

**What was actually there.** `abil_ambush` (Meeps-only) was built during the 23 Aug ability-depth pass entirely on top of Overwatch's own machinery: activating it set both `concealed` AND `overwatch`, so the "ambush shot" fired through the identical reaction-fire trigger a plain held-shot uses — one shot, out of one turn of concealment, and firing broke the cloak the instant it fired (the same line that already made concealment fragile for `abil_screen`). It was a reactive trick, not a posture you could actually play a turn from inside. Underused for exactly that reason: a Meeps that ambushed either got its one shot for free or sat there having spent a whole turn on a shot that never came, and either way the turn after was just an unconcealed Meeps standing wherever it happened to be.

**The fix — three coupled changes, not one.**

*The cloak itself.* `Mission.ambush()` no longer sets `overwatch`. Instead it sets a new field, `BattleUnit.stealthTurnsRemaining` (engine/units.ts), to `AMBUSH_STEALTH_DURATION` (3, data/combatTables.ts) alongside `concealed = true`. The single per-round loop that used to unconditionally clear `concealed` for every posture at the start of each new round (engine/mission.ts, the same loop `overwatch`/`braced`/`taunting` reset in) now checks this field first: while it's still counting down, `concealed` survives the loop instead of being blanket-cleared, and the field itself decrements. `abil_screen`'s concealment never sets this field, so a Munti's screen keeps its original exactly-one-round shape completely untouched — this is additive, not a rewrite of the shared flag's meaning. Because nothing in the codebase ever gated movement on `concealed` (confirmed by grep — the flag is only ever set or cleared, never read as a move-blocker), "can move while stealth" cost no code at all; it was already true. "Can attack while stealth" falls out the same way: a cloaked unit's later turns are just ordinary turns (`move()`, `attack()`, the works) with actions refreshed like anyone else's, until the clock runs out or it fires.

*The decloak bonus.* `resolveAttack()` — the single body every attack in the game funnels through — now checks, before either damage-dealing branch runs, whether the attacker is mid-cloak (`concealed && stealthTurnsRemaining > 0`). If so, the computed damage is multiplied by `AMBUSH_DECLOAK_DAMAGE_MULTIPLIER` (2) before it's applied to the defender, before the lifesteal-on-damage hook reads it, and before it's recorded in the outcome/log — so a decloak strike really did deal double, not just display double. Gated on `stealthTurnsRemaining` specifically rather than `concealed` alone, so a `abil_screen`-covered unit's attack (same `concealed` flag, no duration field) never gets it — the bonus is Ambush's, not concealment's in general. The log now tags the specific attack that triggers it ("— DECLOAK STRIKE") rather than leaving a player to notice an oddly large number. Attacking still clears both `concealed` and `stealthTurnsRemaining` together, same as before — one shot ends the cloak for good, whichever of the three rounds it happens on.

*Giving Sensor Sweep something real to counter.* This is the part that would have made "give sweep a pvp use" false advertising if left alone: `engine/ai.ts`'s `isVisibleTo` checked `target.concealed` and returned "not visible" *before* it ever checked `target.revealedUntilTurn` (the flag `abil_sensor_sweep` paints onto a target). Burrowed units already had the opposite ordering — a sweep's paint beat burrow — but concealment was checked first and returned early, so a swept `abil_ambush` or `abil_screen` unit was still completely invisible no matter how many charges you spent on it. Under the old one-turn-reactive Ambush this was nearly moot; under a 3-round active cloak it would have made Sweep dead weight against the one threat this redesign was explicitly built to make dangerous. Reordered so `revealedUntilTurn` is checked first, same as it already was relative to burrow — a sweep now punches through concealment exactly the way it already punched through burrow, "revealing is not surfacing" applying equally to both. `canSensorSweep` is still player-only today (no hostile-side use exists, so there's no PvP mode yet for the ability to actually run in) — this change is the seam that mode would need, opened now rather than papered over, matching how `abil_missile`'s own "SOFT pass, not granted to any archetype yet" comment already documents unfinished infrastructure honestly elsewhere in this file.

**data/abilities.ts.** `abil_ambush`'s comment rewritten in full for the new mechanic, with the original version kept below a line for history (same convention data/abilities.ts already uses nowhere else yet, but matching the project's general instinct to keep design history in place rather than deleting it — see the Tier 4 addendum's own "naming, flagged not decided" precedent). Activation cost (entire remaining action budget, ends the turn) and the "REFUSED with a hostile already adjacent" gate are both unchanged — this redesign is about what happens *after* a clean activation, not the activation itself.

**Verification.** `npm run typecheck` and `npx eslint` on every changed file: clean. Full `npm test`: the four existing `abilities.test.ts` cases that encoded the old reactive-shot behavior needed rewriting to match the new one (they failed exactly as expected the moment the mechanic changed — not a sign of a bug, a sign the old tests were doing their job) — rewritten to exercise activation, the fog interaction with no more auto-fire, a real move-then-attack-while-cloaked decloak strike, and the full 3-round survive-then-expire lifecycle; one new test added directly to the sensor-sweep block proving a swept unit is now visible through concealment (not just burrow) via `isVisibleTo`, and reverts to hidden once unpainted. 1140/1140, zero regressions elsewhere. Full `npm run lint` (spoiler stage included): clean.

Also ran `npm run sim:batch` (40 missions x 10 runs, the same regression-catching pass Tier 0 built and used this session) — 289/400 (72%) aggregate, matching the existing baseline. Checked, not just run for form: `src/sim/playerAi/` never calls `mission.ambush()` at all (`playerAi/types.ts` documents Ambush/Interdict/Sensor Sweep/Taunt as still not built into the bot's own decision logic), and nothing in the current single-player-vs-hostile sim ever sets `revealedUntilTurn` on a player unit, so both halves of this redesign are provably unreachable by the bot as it stands today — this run is confirmation of zero interference with existing systems, not a live exercise of the new mechanic. A real balance read on the cloak itself only becomes possible once either a player is driving a Meeps by hand or the bot is taught to use Ambush — neither exists yet.

### Delivered files

`src/engine/mission.ts` (`ambush()` rewritten, `resolveAttack()`'s decloak-multiplier check and log tag, the end-of-round loop's stealth-duration handling), `src/engine/units.ts` (new `stealthTurnsRemaining` field), `src/engine/ai.ts` (`isVisibleTo` reordered so a sweep's paint beats concealment), `src/data/combatTables.ts` (`AMBUSH_STEALTH_DURATION`, `AMBUSH_DECLOAK_DAMAGE_MULTIPLIER`), `src/data/abilities.ts` (`abil_ambush` comment rewritten), `src/engine/__tests__/abilities.test.ts` (four tests rewritten, one new test added) — all via the device bridge. `design/Bloom_Wars_Build_Log_Addendum_Tier5AmbushStealthCloakRedesign_30Aug2026.md` (new, this file) — also via the device bridge.

### Still open

The bot's own decision logic still does not use Ambush, Interdict, Sensor Sweep, or Taunt at all (`playerAi/types.ts`'s own note) — this redesign makes Ambush worth teaching the bot, but did not teach it; that is a separate, larger piece of work than this tier's scope. `abil_screen`'s own concealment is now the one place `isVisibleTo`'s reorder has any live effect against a hostile AI that could theoretically be given `revealedUntilTurn` some day — nothing does that today, so this is inert infrastructure, flagged rather than hidden, same discipline as `abil_missile`'s own "not granted to anyone yet" note. The live Playwright walkthrough remains owed across Tiers 1-5 together now; this tier especially has nothing to show visually (no UI touched at all — pure engine), so it would only ever exercise Battle.ts's existing ability buttons against a hand-played Meeps, not anything new this tier built. Tier 6 (enemy variety audit) and the House Amaranth 36-mission track remain untouched.
